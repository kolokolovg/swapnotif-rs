# swapnotif

Демон systemd, который следит за занятостью swap и при превышении порога
присылает уведомление на рабочий стол — с именем приложения, внёсшего
наибольший вклад в рост swap.

Бинарник, deb-пакет и сервис называются `swapnotif`; репозиторий и crate —
`swapnotif-rs` (как `ripgrep` → пакет `ripgrep`).

## Как работает

- каждые 5 секунд читается `/proc/meminfo`; при занятости swap ≥ порога
  (по умолчанию 80%) фиксируется событие «порог превышен»;
- для события определяется приложение с наибольшим приростом `VmSwap` за
  окно атрибуции (по умолчанию 60 с): процессы группируются по cgroup до
  уровня юнита systemd, имя — как у юнита (на cgroup v1 — по имени
  процесса); прирост меньше 50 МБ — «приложение не определено»;
- уведомление (`org.freedesktop.Notifications`) уходит во все активные
  графические сессии: в заголовке — занятость swap, в теле — виновник,
  его прирост и текущая скорость обмена со swap;
- гистерезис и cooldown (по умолчанию 5 мин) защищают от потока
  уведомлений при колебаниях вокруг порога; недоставленное уведомление
  повторяется, пока событие актуально.

## Установка

Deb-пакет для amd64 — со [страницы релизов](https://github.com/kolokolovg/swapnotif-rs/releases):

```
sudo apt install ./swapnotif_<версия>_amd64.deb
```

После установки сервис включён и запущен, настройка не требуется.

> При переходе со старого пакета `swapnotif-rs` (имя до переименования)
> сначала удалите его: `sudo apt remove swapnotif-rs`.

## Конфигурация

Опциональна: `/etc/swapnotif/config.toml`. Пример с комментариями —
`/usr/share/doc/swapnotif/examples/config.example.toml`. Поведение
fail-fast: опечатка в имени ключа или значение вне диапазона — ошибка
старта с сообщением в journald, а не тихий откат к дефолту.

| Параметр | Дефолт | Диапазон | Смысл |
|---|---|---|---|
| `threshold_pct` | 80 | 10–99 | порог занятости swap, % |
| `hysteresis_pct` | 5 | 1–20 | сброс события при падении ниже порог−гистерезис |
| `interval_secs` | 5 | 1–3600 | интервал опроса `/proc` |
| `window_secs` | 60 | 10–3600 | окно атрибуции виновника (эффективное чуть меньше, см. пример) |
| `cooldown_secs` | 300 | 10–86400 | минимальная пауза между уведомлениями |
| `min_culprit_mb` | 50 | 1–10240 | минимальный прирост виновника для попадания в уведомление |

## Управление

```
systemctl status swapnotif
journalctl -u swapnotif -e
sudo systemctl restart swapnotif
```

## Сборка из исходников

```
cargo build --release          # бинарник target/release/swapnotif
dpkg-buildpackage -us -uc -b   # deb: нужны build-essential, debhelper 13, cargo
```

Требования: Linux с systemd; для группировки по приложениям — cgroup v2
(на v1 — атрибуция по имени процесса); менеджер уведомлений рабочего
стола (KDE Plasma, GNOME и т.п.).
