# swap-usage-attribution Specification

## Purpose

Определяет приложение, внёсшее наибольший вклад в рост занятости swap: снапшоты `VmSwap` по процессам, дельты за окно наблюдения, группировка процессов по cgroup до уровня приложения и выбор виновника события превышения.

## Requirements

### Requirement: Снапшоты занятости swap по процессам
The system SHALL на каждом цикле мониторинга снимать снапшот занятости swap по процессам (поле `VmSwap` из `/proc/<pid>/status`), идентифицируя процесс парой `(pid, starttime)` из `/proc/<pid>/stat` для защиты от переиспользования PID.

#### Scenario: Снапшот покрывает все процессы со свап-следом
- **WHEN** в системе есть процессы с ненулевым `VmSwap`
- **THEN** снапшот содержит запись для каждого такого процесса

#### Scenario: Завершение процесса между снапшотами
- **WHEN** процесс завершился между двумя снапшотами
- **THEN** его запись отсутствует в новом снапшоте, и это не ошибка мониторинга

#### Scenario: Переиспользованный PID не наследует след
- **WHEN** PID занят новым процессом с другим `starttime`
- **THEN** система различает эти процессы и не засчитывает старому процессу свап-след нового

### Requirement: Дельты за окно атрибуции
The system SHALL вычислять прирост занятости swap каждого процесса за окно атрибуции (дефолт 60 с) как разность с наиболее старым снапшотом внутри окна.

#### Scenario: Прирост за окно
- **WHEN** процесс имел 100 МБ `VmSwap` в начале окна и 300 МБ в конце окна 60 с
- **THEN** его прирост за окно равен 200 МБ

#### Scenario: Отрицательная дельта трактуется как ноль
- **WHEN** занятость swap процесса за окно уменьшилась
- **THEN** прирост процесса для атрибуции считается нулевым

### Requirement: Группировка процессов по cgroup
The system SHALL группировать процессы по их cgroup v2 пути (строка `0::/...` из `/proc/<pid>/cgroup`), так что вклад оценивается на приложение (юнит), а не на отдельный процесс; при недоступном cgroup v2 пути — деградация до группировки по имени процесса (`comm`).

#### Scenario: Вклад нескольких процессов одного приложения суммируется
- **WHEN** два процесса одной cgroup выросли в swap на 100 МБ и 50 МБ
- **THEN** вклад приложения равен 150 МБ

#### Scenario: Недоступная cgroup не ломает расчёт
- **WHEN** путь cgroup процесса не удалось прочитать (процесс завершился между операциями) или строка `0::` отсутствует (cgroup v1)
- **THEN** процесс группируется по имени процесса (`comm`), а расчёт остальных продолжается

### Requirement: Выбор виновника события
The system SHALL при событии «порог превышен» выбирать приложение с максимальным приростом swap за окно атрибуции как виновника нагрузки.

#### Scenario: Выбор максимума
- **WHEN** приложения выросли в swap на 850 МБ и 300 МБ
- **THEN** виновником признаётся первое

#### Scenario: Имя виновника
- **WHEN** виновник определён
- **THEN** имя приложения берётся из имени юнита cgroup (без суффикса `.service`), а при недоступности юнита — из имени процесса (`comm`)

### Requirement: Порог значимости виновника
The system SHALL указывать «приложение не определено», если прирост виновника меньше минимального веса (дефолт 50 МБ за окно).

#### Scenario: Незначительный прирост не атрибуируется
- **WHEN** максимальный прирост за окно равен 2 МБ при минимальном весе 50 МБ
- **THEN** событие содержит признак «приложение не определено»

#### Scenario: Значительный прирост атрибуируется
- **WHEN** максимальный прирост за окно равен 500 МБ
- **THEN** событие содержит имя приложения и величину прироста
