# daemon-lifecycle Specification

## Purpose

Обеспечивает работу приложения как system-демона systemd и поставку deb-пакетом так, что после установки сервис включён, запущен и работоспособен без каких-либо дополнительных настроек, кроме опционального конфигурационного файла.

## Requirements

### Requirement: Автозапуск при установке пакета
The system SHALL поставляться deb-пакетом с юнитом в `/usr/lib/systemd/system/` так, что установка пакета автоматически включает и запускает демон (механизм `dh_installsystemd`), а удаление пакета останавливает и отключает его стандартными средствами.

#### Scenario: Установка пакета на систему с systemd
- **WHEN** deb-пакет установлен
- **THEN** юнит включён и демон активен без ручных действий пользователя

#### Scenario: Удаление пакета
- **WHEN** deb-пакет удаляется
- **THEN** демон останавливается и юнит отключается стандартными средствами deb-systemd-helper

### Requirement: Юнит systemd с перезапуском
The system SHALL работать как system-сервис с `Type=notify` (готовность сигнализируется через sd_notify `READY=1` после успешной инициализации) и `Restart=on-failure`.

#### Scenario: Готовность после инициализации
- **WHEN** демон успешно инициализирован под systemd
- **THEN** сервис переходит в состояние active после сигнала готовности

#### Scenario: Аварийный перезапуск
- **WHEN** демон завершился с ошибкой
- **THEN** systemd перезапускает сервис в соответствии с `Restart=on-failure`

### Requirement: Изоляция юнита без потери функций
The unit SHALL применять изоляцию (`ProtectSystem=strict`, `RestrictAddressFamilies=AF_UNIX AF_NETLINK`) и при этом сохранять работоспособность мониторинга (`/proc`) и доставки (unix-сокеты D-Bus).

#### Scenario: Мониторинг и доставка работают под изоляцией
- **WHEN** демон запущен юнитом с включённой изоляцией
- **THEN** чтение `/proc`, подключение к logind и user bus сокетам выполняются успешно

### Requirement: Конфигурация с дефолтами в коде
The system SHALL работать без конфигурационного файла, применяя встроенные дефолты (порог 80%, интервал 5 с, окно атрибуции 60 с, cooldown 5 мин, гистерезис 5 п.п., минимальный вес виновника 50 МБ); при наличии `/etc/swapnotif/config.toml` его значения SHALL переопределять дефолты; невалидный конфиг SHALL приводить к завершению с ненулевым кодом и понятным сообщением в логе.

#### Scenario: Работа без конфигурационного файла
- **WHEN** `/etc/swapnotif/config.toml` отсутствует
- **THEN** дем работает со встроенными дефолтами

#### Scenario: Переопределение порога
- **WHEN** конфигурация задаёт порог 90%
- **THEN** событие «порог превышен» срабатывает только при занятости от 90%

#### Scenario: Невалидная конфигурация завершает демон
- **WHEN** конфигурационный файл содержит невалидный TOML, неизвестное поле или значение вне допустимого диапазона
- **THEN** дем завершается с ненулевым кодом и понятным сообщением об ошибке в journald

### Requirement: Журналирование работы
The system SHALL записывать в journald ключевые события: срабатывание порога с деталями события, результат доставки по каждой сессии, предупреждения (нет swap, нет сессий) и ошибки конфигурации.

#### Scenario: Событие порога в журнале
- **WHEN** событие «порог превышен» обработано
- **THEN** в journald есть запись с процентом занятости и результатом атрибуции

#### Scenario: Ошибка доставки в журнале
- **WHEN** подключение к шине сессии не удалось
- **THEN** в journald есть запись с uid сессии и причиной ошибки

### Requirement: CI-сборка deb-пакета
The system SHALL собирать deb-пакет в CI (GitHub Actions, ubuntu-latest) тем же механизмом, что и локальную упаковку (`dpkg-buildpackage -us -uc -b` поверх `debian/`), перед упаковкой прогоняя тесты (`cargo test --locked`); полученный .deb SHALL быть артефактом каждого запуска workflow.

#### Scenario: Сборка по пушу тега
- **WHEN** в репозиторий запушен тег с именем вида `v*`
- **THEN** workflow собирает deb и публикует его как артефакт запуска

#### Scenario: Ручной запуск без публикации
- **WHEN** workflow запущен вручную (`workflow_dispatch`) без флага publish
- **THEN** deb собирается и остаётся артефактом запуска, GitHub Release не создаётся

#### Scenario: Тесты не прошли — пакет не собирается
- **WHEN** `cargo test --locked` завершается с ошибкой
- **THEN** сборка deb не выполняется, запуск workflow помечен как неудачный

### Requirement: Публикация релиза с контролем версии
Workflow SHALL публиковать GitHub Release с собранным .deb и автогенерированными release notes только с тега `v*` и только при совпадении номера тега с версией пакета из `Cargo.toml`; при расхождении публикация SHALL падать с понятным сообщением об ошибке; ручной запуск с флагом publish вне тега SHALL завершаться явной ошибкой, а не тихим пропуском.

#### Scenario: Публикация по тегу
- **WHEN** тег `v0.1.0` совпадает с версией в `Cargo.toml`
- **THEN** создан GitHub Release `v0.1.0` с .deb и автогенерированными notes

#### Scenario: Расхождение тега и версии
- **WHEN** тег `v0.2.0` не совпадает с версией `0.1.0` в `Cargo.toml`
- **THEN** публикация падает с сообщением о расхождении и указанием поднять версию в `Cargo.toml`

#### Scenario: Ручная публикация вне тега
- **WHEN** workflow запущен вручную с флагом publish не на теге `v*`
- **THEN** запуск завершается явной ошибкой с указанием перезапустить на теге

### Requirement: Поставка desktop-файла приложения
The system SHALL поставлять в deb-пакете desktop-файл `/usr/share/applications/swapnotif.desktop` (`Type=Application`, `NoDisplay=true`), чтобы менеджер уведомлений резолвил отправителя `desktop-entry = "swapnotif"` сразу после установки пакета без дополнительных действий пользователя.

#### Scenario: Установка пакета кладёт desktop-файл
- **WHEN** deb-пакет установлен
- **THEN** файл `/usr/share/applications/swapnotif.desktop` существует, объявляет приложение с идентификатором `swapnotif` и не отображается в меню приложений (`NoDisplay=true`)

#### Scenario: Удаление пакета убирает desktop-файл
- **WHEN** deb-пакет удаляется
- **THEN** desktop-файл удаляется стандартными средствами dpkg, без скриптов пакета
