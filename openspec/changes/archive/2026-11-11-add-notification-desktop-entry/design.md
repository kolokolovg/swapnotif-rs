# Design

## Context

Мотивация — в proposal.md («Why»). Доставка работает: вызов `Notify` доходит до plasmashell и возвращает id (лог «уведомление доставлено» честен), но Plasma 6 резолвит отправителя по hint `desktop-entry` и сохраняет в историю только опознанные приложения. Приёмка 2026-11-11 (busctl А/Б на plasmashell 6.6.6): уведомления с `desktop-entry=swapnotif` остаются в истории, без подсказки — отбрасываются. Демон (`src/notify.rs`, `send_notify`) шлёт пустой словарь hints; desktop-файла у пакета нет.

## Goals / Non-Goals

**Goals:**
- Уведомления swapnotif остаются в истории менеджера уведомлений (Plasma 6) без изменений в транспорте доставки.
- «Из коробки»: после установки deb резолв работает сразу, без ручных действий.

**Non-Goals:**
- Кнопки действий, urgency, transient и прочие hints остаются вне скоупа — прежний Non-Goal (архив `2026-11-10-add-swap-monitor-daemon`, D6) сужается ровно на один hint, идентифицирующий отправителя.
- Резолв иконки/имени приложения из desktop-файла в UI уведомления — менеджер сам решает, что с ними делать; файл даёт минимум, нужный для идентификации.
- Гарантии истории в менеджерах, не поддерживающих `desktop-entry` (спека freedesktop считает hints опциональными) — там поведение не меняется и не ухудшается.

## Decisions

### D1. Идентификация: hint `desktop-entry` (не резолв по имени)
Значение — строка `swapnotif` (variant `s` в словаре `a{sv}`): идентификатор desktop-файла по спеке `org.freedesktop.Notifications`. Приёмка подтвердила, что Plasma 6 матчит по нему детерминированно.
*Альтернативы:* резолв по `app_name` из вызова — не по спеке и ненадёжен (матчинг имён у менеджеров различается); hint `transient`, чтобы не путать историю — противоположная цель; путь к файлу в значении hint — против спеки (ожидается file id).

### D2. Desktop-файл: `packaging/swapnotif.desktop`, явная установка в `debian/rules`
Файл-источник в новом каталоге `packaging/` (минимум: `Type=Application`, `Name=swapnotif`, `Exec=/usr/bin/swapnotif`, `NoDisplay=true`, `Terminal=false`), установка — дополнительный `install -Dm644` в существующий `override_dh_auto_install` рядом с бинарником.
*Альтернативы:* `debian/swapnotif.desktop` + `dh_installdesktop` — идиоматично, но подключает поведение debhelper (compat ≥ 12) и двойные пути установки с явным `install`; каталог `assets/` — файл существует только ради deb. Идентификатор `swapnotif` совпадает с `APP_NAME`, именем пакета, юнита и бинарника — один токен на всё (D4 прежнего design).

### D3. `NoDisplay=true` вместо обычного файла меню
Демон без GUI: в меню приложений ему нечего показывать, а для резолва уведомлений `NoDisplay=true` не мешает (менеджер ищет файл по id, а не показывает его).
*Альтернативы:* файл без `NoDisplay` — мусорная кнопка в меню, запускающая демона в сессии; `X-GNOME-Autostart`-хитрости — не нужны, демона запускает systemd-юнит.

## Risks / Trade-offs

- [Менеджер уведомлений без поддержки `desktop-entry` игнорирует подсказку] → поведение идентично текущему, спека freedesktop считает hints опциональными; регрессии нет.
- [Живая машина с уже запущенной Plasma кэширует список desktop-файлов] → приёмка показала, что подхват происходит без перезапуска plasmashell (файл появился в `~/.local/share/applications` — уведомления №2/№3 сразу попали в историю); для deb это путь `/usr/share/applications`, обновление кэша срабатывает аналогично, при необходимости — `kbuildsycoca6` (задокументировать в README не требуется).
- [Имя `swapnotif` когда-нибудь разойдётся с именем пакета/бинарника] → hint и файл зависят от одного токена; тест упадёт при расхождении `APP_NAME` и значения hint (см. tasks).

## Migration Plan

Обычный релиз: новая версия пакета при обновлении кладёт desktop-файл, откат — возврат на предыдущую версию (файл уберёт dpkg). Обратная совместимость полная: подсказка опциональна, транспорт и протокол доставки не меняются.
